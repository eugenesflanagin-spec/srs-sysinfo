# SRS 1.1.2 - IPI Delay worked example

A small update to 1.1.1.

## What's new

- **New guide page: "Reading the CPU IPI Delay table - a worked example"** (User Guide 9.2.2).
  One Ryzen 7 7800X3D's full 16 x 16 IPI Delay result, explained step by step: how to read the
  table, why the two threads of a core are the fastest pair (23-25 ns), why other pairs are 27-34 ns,
  what a CPU with two CCDs typically looks like, and what the table is useful for (finding partner
  threads, the CCD layout, pinning game and audio threads). The IPI Delay item's Guide button (F1)
  leads to it.
- **Fixed: a burn-in run could be saved twice** when the CPU Burnin and CPU Stress windows were both
  open. Each finished run is now saved to one `~/.cache/srs/burnin-YYYYMMDD-HHMMSS.txt` file.

Full list in [CHANGELOG.md](CHANGELOG.md).

## Install

**Arch Linux**

```sh
sudo pacman -U srs-sysinfo-1.1.2-1-x86_64.pkg.tar.zst
# or from the AUR:  yay -S srs-sysinfo
```

**Debian / Ubuntu**

```sh
sudo apt install ./srs-sysinfo_1.1.2-1.deb13_amd64.deb        # or the .ubuntu24.04 file
```

**Fedora / openSUSE**

```sh
sudo dnf install ./srs-sysinfo-1.1.2-1.fc44.x86_64.rpm
sudo zypper install ./srs-sysinfo-1.1.2-1.tw.x86_64.rpm
```

**Any other distribution**

```sh
tar xf srs-sysinfo-1.1.2-linux-x86_64.tar.gz
cd srs-sysinfo-1.1.2-linux-x86_64
./usr/bin/srs-gui                     # run in place, or install:
sudo cp -r usr/bin usr/share /usr/local/
```

`INSTALL.txt` in the tarball covers the optional boot-time service and uninstalling.

## Requirements

- 64-bit x86 Linux. Use the package for your distro; the generic `linux-x86_64.tar.gz` is built from the
  Ubuntu 24.04 package and needs glibc 2.38 or newer (check with `ldd --version`)
- GTK 3, GLib, Pango, Cairo, and `hwdata`
- Optional, for more detail: polkit (for `srs-root`), dmidecode, smartmontools, nvme-cli, i2c-tools,
  pciutils, usbutils, lm-sensors, vulkan-tools, clinfo, mesa-utils, libayatana-appindicator (tray icon)
- For guide links at the exact page: Okular, Evince or Papers (other viewers open the HTML guide)

## Upgrading from 1.1.1 or 1.1.0

Nothing to do: settings, the boot-time service and saved benchmark results carry over.
