# SRS 2.2.1 - fixes for GPU Burnin, CPU Burnin and the main window

A small update to SRS 2.2 with fixes found in the final review of 2.2.0. Nothing else changes:
everything from 2.2 is still there, and settings, tabs and lineups carry over.

## What's fixed

- **After a GPU driver call that never came back**, the next GPU test no longer says "GPU Burnin is
  running; wait for it to finish". It says that a GPU call did not return earlier and that SRS (or the
  PC) must be restarted. CPU Burnin / Stress, which does not start while a GPU test holds the GPU,
  now shows why in its status line instead of doing nothing when you press Start.
- **GPU Burnin on All GPUs**: a card that cannot start (for example it cannot do FP64) is marked
  "COULD NOT START" in the table, and the verdict comes from the cards that did run. Before, the whole
  run was reported as "ended early by a safety rule" although the other cards had passed. If no card
  can start, the run says so. The command line prints the same note.
- **GPU Compute comparison**: pressing Run while SRS is still checking which back ends are installed
  says "Checking which back ends are installed..." instead of asking you to tick a back end that is
  still greyed out.
- **The main window** (and the other windows) no longer ask for more room than the screen has: the
  default size is limited to about 90% of the monitor's work area.
- The "CPU Burnin and GPU tests never start together" check no longer relies on x86 memory ordering,
  so it holds on ARM as well (the flag is now a proper atomic).
- The screenshots in the user guide that show the Benchmarks and Tools pages and the classic menu
  are retaken for the 2.2 look.

Full list in [CHANGELOG.md](CHANGELOG.md); [CREDITS.md](CREDITS.md) lists the public data and the credits.

## Tested on one PC (and what that means)

I build and test SRS on a single machine: a Ryzen 7 7800X3D with a Radeon RX 9070 XT, on a wired
connection. I've done everything I can for the rest (checks that don't need the hardware, careful
reading of the docs, test builds), but I can't try what I don't own. So anything that needs other
hardware, such as NVIDIA CUDA (and ZLUDA), Intel graphics, ROCm/HIP or OpenCL setups other than
mine, Wi-Fi or VPN network tests, or ARM and 32-bit builds, may have a bug or two I haven't met yet. If you find one, please tell me: open an issue on
[GitHub](https://github.com/eugenesflanagin-spec/srs-sysinfo/issues) with your hardware and the
report SRS made, and I'll fix it.

Not tried on real hardware so far:

- GPU benchmarks: the Vulkan tests, GPU Burnin and the GPU Compute comparison were run only on
  lavapipe (the Mesa software renderer, which runs on the CPU), with small sizes, so the logic, the
  error counting, Stop and the result pages are checked; the Vulkan type layouts were checked
  against the official Khronos header for 64-bit and 32-bit builds. ROCm/HIP, CUDA and OpenCL were
  tried only in part: the libraries load and every function SRS needs is found in them (on my own
  ROCm, my ZLUDA and my OpenCL loader too), and a missing library or an OpenCL loader with no
  driver is handled cleanly, but no HIP, CUDA or OpenCL work was run on a GPU. Not run on real
  hardware: Vulkan on a real GPU, GPU Burnin on a real GPU, CUDA on NVIDIA, ZLUDA, ROCm/HIP on AMD,
  OpenCL on AMD (ROCm) and Mesa Rusticl, anything on Intel graphics, and the temperature, power,
  clock and fan read-outs for NVIDIA and Intel.
- ARM (aarch64) and 32-bit (i686) builds: compile-checked only.
- OS Latency: run only with the scx_lavd scheduler; BORE, EEVDF and CFS are recognised but were
  not run here.
- CPU Compute: the AVX-512 code has only run on a Zen 4 CPU; the SSE2 and AVX2 code was checked by
  forcing it on that same CPU, not on older CPUs.
- Everyday Work: run with the compression libraries of one Arch Linux system; other versions
  should work but give different speeds.
- Network: run on one wired Ethernet connection only; Wi-Fi, VPN and metered or mobile
  connections are untested. The internet speed test was run once on that connection, against
  Cloudflare, with sensible results (download several hundred Mbit/s, upload about 60 Mbit/s), and
  the report showed no IP address, host name or MAC address.

**Things to know about the GPU tests**

- A back end that is not installed shows as "not installed" with a one-line hint (for example
  "install ROCm"); the others still run.
- If your CUDA library is really ZLUDA (CUDA calls translated to an AMD GPU), the column is
  labelled "CUDA (ZLUDA)".
- Every OpenCL driver is its own column, for example "OpenCL (ROCm)" and "OpenCL (Rusticl)" on the
  same GPU; CPU drivers (PoCL) are marked CPU.
- Speeds are only comparable between alike SRS builds and the same GPU driver / runtime versions.
- GPU Burnin ends by itself on a driver error, a GPU that stops answering, a piece of work that
  takes far too long, or a temperature at the limit (default 100 °C). It never changes clocks,
  voltages or fans. It asks before it starts. It never burns a software renderer (such as
  llvmpipe) as if it were a GPU, and when a card reports no temperature to SRS the result says that
  the temperature limit was not active.
- Opening a GPU window's list of GPUs, or pressing Run, reads the list of GPUs through Vulkan, the
  way `vulkaninfo` does: the GPUs are named, no work is sent to them until you answer Yes. ROCm /
  HIP, CUDA and OpenCL are started only after Yes (in GPU Burnin the GPU you picked is found in
  their own list by its PCI address).

## Install

**Arch Linux**

```sh
sudo pacman -U srs-sysinfo-2.2.1-1-x86_64.pkg.tar.zst
# or from the AUR:  yay -S srs-sysinfo
```

**Debian / Ubuntu**

```sh
sudo apt install ./srs-sysinfo_2.2.1-1.deb13_amd64.deb        # or the .ubuntu24.04 file
```

**Fedora / openSUSE**

```sh
sudo dnf install ./srs-sysinfo-2.2.1-1.fc44.x86_64.rpm
sudo zypper install ./srs-sysinfo-2.2.1-1.tw.x86_64.rpm
```

**Any other distribution**

```sh
tar xf srs-sysinfo-2.2.1-linux-x86_64.tar.gz
cd srs-sysinfo-2.2.1-linux-x86_64
./usr/bin/srs-gui                     # run in place, or install:
sudo cp -r usr/bin usr/share /usr/local/
```

`INSTALL.txt` in the tarball covers the optional boot-time service and uninstalling.

**AppImage (any distribution)**

```sh
chmod +x srs-sysinfo-2.2.1-x86_64.AppImage
./srs-sysinfo-2.2.1-x86_64.AppImage
```

With arguments it is the command line (`--version`, `find ...`, `srs-sysreport`). Run as root
works from it; the boot-time refresh needs the package for your distro. AppImageUpdate (or a
manager that uses it, such as AppImageLauncher) keeps it up to date.

## Requirements

- 64-bit x86 Linux. Use the package for your distro; the generic `linux-x86_64.tar.gz` is built from the
  Ubuntu 24.04 package and needs glibc 2.38 or newer (check with `ldd --version`)
- GTK 3, GLib, Pango, Cairo, SQLite 3 (for Power & cost), and `hwdata`
- Optional, for more detail: polkit (for `srs-root`), dmidecode, smartmontools, nvme-cli, i2c-tools,
  pciutils, usbutils, lm-sensors, vulkan-tools, clinfo, mesa-utils, libayatana-appindicator (tray icon);
  zlib, zstd, lz4 and xz (liblzma) for the Everyday Work benchmark's compression rows (almost every
  system has them); libcurl for the Network benchmark's internet speed test; the Vulkan loader and
  your GPU's Vulkan driver for the GPU benchmarks; ROCm (HIP), CUDA or an OpenCL driver (with
  CLBlast) only if you want those back ends in GPU Burnin and the GPU Compute comparison
- For guide links at the exact page: Okular, Evince or Papers (other viewers open the HTML guide)

## Upgrading from 2.2.0

Install the new package over the old one; nothing has to be set up again.
