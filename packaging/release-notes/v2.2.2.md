# SRS 2.2.2 - fix for a crash in GPU Comparison and GPU Burnin

A small update to SRS 2.2 with one fix, found by a user who ran the GPU Comparison with CUDA on
an AMD card through ZLUDA. Nothing else changes: everything from 2.2 is still there, and settings,
tabs and lineups carry over.

## What's fixed

- **GPU Comparison and GPU Burnin could crash** (the program ended with a segmentation fault) when
  the vendor GEMM library (hipBLAS or cuBLAS) was measured before SRS's own kernels had been
  loaded. The library test checks every result with one of SRS's own small kernels, and that
  kernel was only loaded for the own-kernel test; when the own-kernel test did not run first or
  failed, the library test handed the GPU driver an empty kernel and the driver crashed. The
  kernels are now always loaded first, and SRS refuses to start a kernel that is not loaded, with
  a message instead of a crash.
- **Without the runtime compiler** (libnvrtc for CUDA, libhiprtc for ROCm / HIP) the library test
  now says "needs the runtime compiler (...) for the error check, and it is not installed", in the
  GPU Comparison result and in GPU Burnin, instead of failing in a confusing way.
- GPU Comparison now says why a test is "not available" (for example that FP16 is measured through
  the GEMM library only) in the notes under the table.

Full list in [CHANGELOG.md](CHANGELOG.md); [CREDITS.md](CREDITS.md) lists the public data and the credits.

## Tested on one PC (and what that means)

I build and test SRS on a single machine: a Ryzen 7 7800X3D with a Radeon RX 9070 XT, on a wired
connection. I've done everything I can for the rest (checks that don't need the hardware, careful
reading of the docs, test builds), but I can't try what I don't own. So anything that needs other
hardware, such as NVIDIA CUDA (and ZLUDA), Intel graphics, ROCm/HIP or OpenCL setups other than
mine, Wi-Fi or VPN network tests, or ARM and 32-bit builds, may have a bug or two I haven't met yet. If you find one, please tell me: open an issue on
[GitHub](https://github.com/eugenesflanagin-spec/srs-sysinfo/issues) with your hardware and the
report SRS made, and I'll fix it.

  Cloudflare, with sensible results (download several hundred Mbit/s, upload about 60 Mbit/s), and
  the report showed no IP address, host name or MAC address.

**Things to know about the GPU tests**

- A back end that is not installed shows as "not installed" with a one-line hint (for example
  "install ROCm"); the others still run.
- If your CUDA library is really ZLUDA (CUDA calls translated to an AMD GPU), the column is
  labelled "CUDA (ZLUDA)".
- Every OpenCL driver is its own column, for example "OpenCL (ROCm)" and "OpenCL (Rusticl)" on the
  same GPU; CPU drivers (PoCL) are marked CPU.
- Speeds are only comparable between alike SRS builds and the same GPU driver / runtime versions.
- GPU Burnin ends by itself on a driver error, a GPU that stops answering, a piece of work that
  takes far too long, or a temperature at the limit (default 100 °C). It never changes clocks,
  voltages or fans. It asks before it starts. It never burns a software renderer (such as
  llvmpipe) as if it were a GPU, and when a card reports no temperature to SRS the result says that
  the temperature limit was not active.
- Opening a GPU window's list of GPUs, or pressing Run, reads the list of GPUs through Vulkan, the
  way `vulkaninfo` does: the GPUs are named, no work is sent to them until you answer Yes. ROCm /
  HIP, CUDA and OpenCL are started only after Yes (in GPU Burnin the GPU you picked is found in
  their own list by its PCI address).

## Install

**Arch Linux**

```sh
sudo pacman -U srs-sysinfo-2.2.2-1-x86_64.pkg.tar.zst
# or from the AUR:  yay -S srs-sysinfo
```

**Debian / Ubuntu**

```sh
sudo apt install ./srs-sysinfo_2.2.2-1.deb13_amd64.deb        # or the .ubuntu24.04 file
```

**Fedora / openSUSE**

```sh
sudo dnf install ./srs-sysinfo-2.2.2-1.fc44.x86_64.rpm
sudo zypper install ./srs-sysinfo-2.2.2-1.tw.x86_64.rpm
```

**Any other distribution**

```sh
tar xf srs-sysinfo-2.2.2-linux-x86_64.tar.gz
cd srs-sysinfo-2.2.2-linux-x86_64
./usr/bin/srs-gui                     # run in place, or install:
sudo cp -r usr/bin usr/share /usr/local/
```

`INSTALL.txt` in the tarball covers the optional boot-time service and uninstalling.

**AppImage (any distribution)**

```sh
chmod +x srs-sysinfo-2.2.2-x86_64.AppImage
./srs-sysinfo-2.2.2-x86_64.AppImage
```

With arguments it is the command line (`--version`, `find ...`, `srs-sysreport`). Run as root
works from it; the boot-time refresh needs the package for your distro. AppImageUpdate (or a
manager that uses it, such as AppImageLauncher) keeps it up to date.

## Requirements

- 64-bit x86 Linux. Use the package for your distro; the generic `linux-x86_64.tar.gz` is built from the
  Ubuntu 24.04 package and needs glibc 2.38 or newer (check with `ldd --version`)
- GTK 3, GLib, Pango, Cairo, SQLite 3 (for Power & cost), and `hwdata`
- Optional, for more detail: polkit (for `srs-root`), dmidecode, smartmontools, nvme-cli, i2c-tools,
  pciutils, usbutils, lm-sensors, vulkan-tools, clinfo, mesa-utils, libayatana-appindicator (tray icon);
  zlib, zstd, lz4 and xz (liblzma) for the Everyday Work benchmark's compression rows (almost every
  system has them); libcurl for the Network benchmark's internet speed test; the Vulkan loader and
  your GPU's Vulkan driver for the GPU benchmarks; ROCm (HIP), CUDA or an OpenCL driver (with
  CLBlast) only if you want those back ends in GPU Burnin and the GPU Compute comparison
- For guide links at the exact page: Okular, Evince or Papers (other viewers open the HTML guide)

## Upgrading from 2.2.0 or 2.2.1

Install the new package over the old one; nothing has to be set up again.
