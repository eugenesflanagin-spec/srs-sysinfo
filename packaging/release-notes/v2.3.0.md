# SRS 2.3.0 - CUDA without the NVIDIA toolkit, clearer OpenCL FP64, an explained CUDA toolkit option

An update to SRS 2.2 for the GPU tests. Everything from 2.2 is still there, and settings, tabs and
lineups carry over.

## What's new

- **CUDA works without the NVIDIA runtime compiler.** SRS's own small GPU test programs (the
  "kernels") now come pre-built inside SRS, as PTX - NVIDIA's portable GPU code, which the graphics
  driver (or ZLUDA) finishes for your card when a test starts. Before, SRS needed NVIDIA's runtime
  compiler (NVRTC, `libnvrtc`) to build them, and ZLUDA does not have one, so every CUDA (ZLUDA) row
  said "not available". Now GPU Burnin and every CUDA row of the GPU Compute comparison, including
  the cuBLAS rows, run without it. The kernels are exactly the ones NVRTC builds (same source,
  names and parameters); NVRTC is only used if a driver refuses the pre-built ones. They are made
  with clang for PTX ISA 6.0 / `sm_50`, which current NVIDIA drivers (CUDA 9 and newer) accept and
  compile on to any newer card.
- **OpenCL FP64 is clearer.** On OpenCL drivers without double precision (often Mesa's Rusticl)
  the FP64 rows said "failed" with an empty reason. They now say "not available: this OpenCL
  driver has no FP64 (double precision)", the CLBlast FP64 row too, and a kernel that does not
  build always shows the OpenCL error code.
- **The NVIDIA CUDA toolkit, explained and optional.** The NVIDIA CUDA toolkit is NVIDIA's free set
  of developer tools for running programs on NVIDIA graphics cards. SRS only needs one small part
  of it, the runtime compiler (NVRTC), and since 2.3 only as a fallback, so most people do not
  need it. When it is missing and it could matter (an NVIDIA card or a CUDA library is there), SRS
  asks **once**, the first time you run a CUDA test: **Install...**, **Not now** or **Don't ask
  again**. If you skip it, you can install it later from **Options -> NVIDIA CUDA toolkit for GPU
  tests...** (or `sysreport-search cuda-toolkit --install`). SRS shows the exact command first
  (Arch: `sudo pacman -S --needed cuda`, about 2.4 GB to download; Debian / Ubuntu: `sudo apt-get
  install libnvrtc12` or `libnvrtc11.2`, about 20 MB; Fedora, openSUSE: instructions for NVIDIA's
  repository), runs it in a terminal window only after you confirm, and tells you how it went. It
  will not start while a benchmark or burn-in runs, while another update holds the package
  database, or without a network connection. The package manager, `sudo` and `pkexec` are only
  taken from `/usr/bin`, `/usr/sbin`, `/bin` or `/sbin` and run by their full path: a program of
  the same name in your own folders (for example `~/.local/bin`) is never run as administrator.
  Without a terminal program it uses `pkexec` and the package manager's "no questions" switch;
  pacman's `--noconfirm` then answers its questions with the defaults, which means **no** to
  removing a conflicting package (the install stops instead). With ZLUDA, `pkexec` is never used.
- The CUDA and HIP columns' "software" line now says whether the own kernels are built in or need
  the runtime compiler.

> **ZLUDA users (AMD cards): do not install the NVIDIA CUDA toolkit.** It can break or remove
> ZLUDA: on Arch the `cuda` package puts NVIDIA's own cuBLAS on the library path, where it can take
> the place of ZLUDA's, and anything that brings NVIDIA's driver libraries (`nvidia-utils`) removes
> ZLUDA, which conflicts with them. SRS 2.3's built-in CUDA tests already work with ZLUDA. SRS warns
> about this in red, makes Cancel the default and asks twice before it installs anything.

Full list in [CHANGELOG.md](CHANGELOG.md).

Tested on the real card (2026-10-29): with ZLUDA (preview build, no NVRTC) on the Radeon RX 9070 XT,
every CUDA row of the GPU Compute comparison ran from the built-in kernels - own-kernel FP32 matrix multiply 5377 GFLOPS, cuBLAS FP32 16392, cuBLAS FP16 77046, own-kernel FP64 860 GFLOPS. ZLUDA's cuBLAS has no FP64
matrix multiply (it answers "not supported", error 15), so that one row says "not available". GPU
Burnin with the CUDA back end was **not** run on the real card.

## Tested on one PC (and what that means)

I build and test SRS on a single machine: a Ryzen 7 7800X3D with a Radeon RX 9070 XT, on a wired
connection. I've done everything I can for the rest (checks that don't need the hardware, careful
reading of the docs, test builds), but I can't try what I don't own. So anything that needs other
hardware, such as NVIDIA CUDA, Intel graphics, ROCm/HIP or OpenCL setups other than mine, Wi-Fi or
VPN network tests, or ARM and 32-bit builds, may have a bug or two I haven't met yet. If you find
one, please tell me: open an issue on
[GitHub](https://github.com/eugenesflanagin-spec/srs-sysinfo/issues) with your hardware and the
report SRS made, and I'll fix it.

What this means for 2.3 in particular:

- The **built-in CUDA kernels** were checked without a GPU (their PTX text against the kernel
  source: names, order, parameter types, nothing outside called; and against a fake CUDA driver in
  the automatic tests), and then run through ZLUDA on my AMD RX 9070 XT in the GPU Compute
  comparison (above). They were **never run on NVIDIA hardware**: "PTX ISA 6.0 / `sm_50`" is what
  NVIDIA's drivers compile on for the card, not something the toolkit version decides. If your
  NVIDIA driver (or another ZLUDA version) refuses them, SRS falls back to NVRTC when it is
  installed, and tells you so when it is not - please report it with your driver version.
- **GPU Burnin with CUDA** (built-in kernels) ran only against the fake driver; not on the real
  card, neither through ZLUDA nor on NVIDIA.
- The **NVIDIA CUDA toolkit install** was tested with fake package managers only (nothing was
  installed); the Debian package names come from Debian's package archive, Ubuntu's are inferred
  from the versions of its nvidia-cuda-toolkit source (SRS asks apt which one exists before it
  offers one), and Fedora and openSUSE get instructions only.
- The **OpenCL FP64** check was tested against a fake OpenCL driver, not on Rusticl itself.
- Everything else as in 2.2: the Vulkan tests, GPU Burnin and the GPU Compute comparison were run
  only on lavapipe (the Mesa software renderer); ROCm/HIP, NVIDIA CUDA and OpenCL only as far as
  loading their libraries and the fake-runtime tests (CUDA through ZLUDA: the GPU Compute
  comparison, above). Not run on real hardware: Vulkan on a real GPU, GPU Burnin on a real GPU (any
  back end, CUDA through ZLUDA included), CUDA on NVIDIA, ROCm/HIP on AMD, OpenCL on AMD (ROCm) and
  Mesa Rusticl, anything on Intel graphics, and the NVIDIA and Intel sensor read-outs. ARM (aarch64)
  and 32-bit (i686) builds: compile-checked only.

## Install

**Arch Linux**

```sh
sudo pacman -U srs-sysinfo-2.3.0-1-x86_64.pkg.tar.zst
# or from the AUR:  yay -S srs-sysinfo
```

**Debian / Ubuntu**

```sh
sudo apt install ./srs-sysinfo_2.3.0-1.deb13_amd64.deb        # or the .ubuntu24.04 file
```

**Fedora / openSUSE**

```sh
sudo dnf install ./srs-sysinfo-2.3.0-1.fc44.x86_64.rpm
sudo zypper install ./srs-sysinfo-2.3.0-1.tw.x86_64.rpm
```

**Any other distribution**

```sh
tar xf srs-sysinfo-2.3.0-linux-x86_64.tar.gz
cd srs-sysinfo-2.3.0-linux-x86_64
./usr/bin/srs-gui                     # run in place, or install:
sudo cp -r usr/bin usr/share /usr/local/
```

`INSTALL.txt` in the tarball covers the optional boot-time service and uninstalling.

**AppImage (any distribution)**

```sh
chmod +x srs-sysinfo-2.3.0-x86_64.AppImage
./srs-sysinfo-2.3.0-x86_64.AppImage
```

With arguments it is the command line (`--version`, `find ...`, `srs-sysreport`). Run as root
works from it; the boot-time refresh needs the package for your distro. AppImageUpdate (or a
manager that uses it, such as AppImageLauncher) keeps it up to date.

## Requirements

- 64-bit x86 Linux. Use the package for your distro; the generic `linux-x86_64.tar.gz` is built from the
  Ubuntu 24.04 package and needs glibc 2.38 or newer (check with `ldd --version`)
- GTK 3, GLib, Pango, Cairo, SQLite 3 (for Power & cost), and `hwdata`
- Optional, for more detail: polkit (for `srs-root`), dmidecode, smartmontools, nvme-cli, i2c-tools,
  pciutils, usbutils, lm-sensors, vulkan-tools, clinfo, mesa-utils, libayatana-appindicator (tray icon);
  zlib, zstd, lz4 and xz (liblzma) for the Everyday Work benchmark's compression rows (almost every
  system has them); libcurl for the Network benchmark's internet speed test; the Vulkan loader and
  your GPU's Vulkan driver for the GPU benchmarks; ROCm (HIP), CUDA (the NVIDIA driver, or ZLUDA)
  or an OpenCL driver (with CLBlast) only if you want those back ends in GPU Burnin and the GPU
  Compute comparison. The NVIDIA CUDA toolkit is **not** needed (see above)
- For guide links at the exact page: Okular, Evince or Papers (other viewers open the HTML guide)

## Upgrading from 2.2.x

Install the new package over the old one; nothing has to be set up again.
