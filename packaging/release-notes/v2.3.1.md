# SRS 2.3.1 - One Stress & Burnin for CPU and GPU, tools as tabs, columns that line up

An update to SRS 2.3. Everything from 2.3 is still there, and settings, tabs and lineups carry over.

## What's new

- **Stress & Burnin: the CPU and the graphics card in one place.** CPU Burnin, CPU Stress and GPU
  Burnin are now one window (a tab in the new main window). Tick **CPU load** and choose **Timed**
  (burn and cool cycles, Pass or Fail) or **Until Stop**; tick **GPU Burnin** to load the graphics
  card at the same time, for its own **Time** or with **Sync to CPU stress time**. The GPU's back end,
  card, precision and temperature limit sit under a folded **GPU options**. Untick CPU load to test
  only the GPU. Your own GPU stress program still works as **Custom GPU command**. The GPU part runs
  as its own small process, so a GPU driver that hangs cannot freeze SRS, and Stop always works.
- **Every tool is a tab.** In the new main window the Benchmarks & Stress page shows each tool as a
  tab with its controls and live results in the page - no more pop-up windows - and compact sections
  at the top to jump to them. Leaving a test that is still running asks whether to stop it. Classic
  View keeps the separate windows.
- **Use at your own risk.** Stress tests and benchmarks push the PC to its limits. The first time you
  start one, SRS shows plain-English terms (provided as is, without warranty; save your work first)
  with **I Agree** / **I Disagree**; nothing starts until you agree. **Options -> Load test terms
  (warranty)...** shows them again. On the command line, `--yes` counts as agreeing.
- **Columns line up on every page.** Each column is as wide as its longest entry, so long device names
  no longer push the next columns out of line (PCI bus, PnP Manager, USB, Processes and more). Very long
  entries end in "..." - hover for the full text; Copy always gives it in full.
- **NUMA memory speed** can run the memory latency test right on its page; **MSR Setup** now explains
  the CPU registers SRS read (P-state clocks, boost, SVM, CPPC ranking) in plain English.
- The mouse wheel over a side tab list moves to the tab above or below. The first time the close button
  only hides SRS to the tray, it says so and how to quit. Page names are capitalised: Benchmarks &
  Stress, Power & Cost, Graphics & Audio.

## Tested on one PC (and what that means)

I build and test SRS on a single machine: a Ryzen 7 7800X3D with a Radeon RX 9070 XT, on a wired
connection. I've done everything I can for the rest (checks that don't need the hardware, careful
reading of the docs, test builds), but I can't try what I don't own. So anything that needs other
hardware, such as NVIDIA CUDA, Intel graphics, ROCm/HIP or OpenCL setups other than mine, Wi-Fi or
VPN network tests, or ARM and 32-bit builds, may have a bug or two I haven't met yet. If you find
one, please tell me: open an issue on
[GitHub](https://github.com/eugenesflanagin-spec/srs-sysinfo/issues) with your hardware and the
report SRS made, and I'll fix it.

What this means for 2.3.1 in particular: the built-in GPU Burnin inside Stress & Burnin was tested on
Mesa's software renderer (lavapipe), not on a real graphics card; the custom GPU command path was run
on the author's card together with a CPU Burnin and passed. The MSR decoding was checked on one AMD
Zen 4 CPU only.

## Upgrading from 2.3.0

Install the new package over the old one; nothing has to be set up again. The first stress test or
benchmark you start asks you to agree to the load test terms once.
